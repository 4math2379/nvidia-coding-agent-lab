Flows, step by step

    Security

    • Bearer key on every route: vLLM alone only checks /v1/*, so coder/auth.py runs as vLLM middleware and refuses /invocations, /metrics and the rest without the key. /health stays open. The key (VLLM_API_KEY) never goes on the command line or in logs.
    • GPU wake-ups: any request reaching the Modal URL starts the GPU before the key is checked. Keep the URL private, or deploy with CODER_PROXY_AUTH=1 so the proxy refuses requests without a Modal proxy token.
    • Pinned revisions: each model is served from a fixed Hugging Face commit, so --trust-remote-code only runs reviewed code.
    • Secrets live in Modal Secrets (huggingface-secret, nemotron-api-key) and are injected as environment variables at startup.
    • No keys in Zed's settings.json or in the repo: .env is git-ignored and keys are entered in the editor UI.
    • TLS to build.nvidia.com, the Modal proxy and the MCP servers.
    • Isolation: gVisor sandboxes on Modal; max_containers=1 also caps the bill.
    • CUDA MCP: OAuth sign-in with an NVIDIA Developer account.
    • Availability: MTP speculative decoding is off because it crashed the GPU (Xid 31); the client retries twice if the engine dies.
    • Rotation: modal secret create --force, then redeploy.
    • On-prem: mirrored images and weights, HF_HUB_OFFLINE=1, isolated InfiniBand partitions, no outbound calls at runtime.

    Measured on 2026-10-27: Super-VL 0.4 s to first token and 64 tok/s, Lightning 0.2 s and 98 tok/s, vLLM on an RTX PRO 6000 ~88 tok/s at $3.03/h. Code: github.com/4math2379/nvidia-coding-agent-lab.
